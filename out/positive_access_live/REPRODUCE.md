# Reproducing the positive ACCESS validation experiment

This experiment is opt-in and isolated. It does not touch the baseline run in
`out/integrated_experiment_20260824_000517` or the corrected replay run in
`out/derived_experiment_20260908`, both of which were verified byte-identical
after this experiment was executed.

No credential is committed to this repository. The token is issued at runtime by
the local Gitea instance and passed through the `GITEA_PAC_TOKEN` environment
variable. It is never written to any JSONL stream, result file, log or figure.

## Environment as executed

| Component | Value |
|---|---|
| Docker Engine | 29.7.2 |
| Gitea | 1.22.6 (`/api/v1/version`) |
| Nmap image | `instrumentisto/nmap` (Nmap 7.98) |
| Host address used | `10.41.159.81` |

The host address matters. It must be one that is reachable **both** from the
Windows host (so the git remote and the token actually work) and from inside a
container (so the active collector can scan it). Loopback does not satisfy both:
the scanner inside a container sees the Docker gateway instead. Substitute an
address valid on your own machine.

## Steps

**1. Start the testbed.**
```
cd testbed && docker compose up -d
docker inspect --format '{{.State.Health.Status}}' testbed-gitea-1   # wait for: healthy
```

**2. Create a user and issue a real token.** The token is generated by Gitea, not
by us.
```
docker exec -u git testbed-gitea-1 gitea admin user create \
    --username pactest --password '<choose>' \
    --email pactest@corp-testbed.local --admin --must-change-password=false

curl -s -u pactest:'<choose>' -H 'Content-Type: application/json' \
     -d '{"name":"pac-live","scopes":["write:repository","read:user"]}' \
     http://<HOST>:3000/api/v1/users/pactest/tokens
```
Take the `sha1` field from the response and export it, without echoing it:
```
export GITEA_PAC_TOKEN=<token>          # PowerShell: $env:GITEA_PAC_TOKEN = '<token>'
```

**3. Verify the token authenticates.** This must return the issuing account, and
a deliberately wrong token must return 401.
```
curl -s -H "Authorization: token $GITEA_PAC_TOKEN" http://<HOST>:3000/api/v1/user
```

**4. Create the target repository** (basic auth; the token scope above does not
include `write:user`).
```
curl -s -u pactest:'<choose>' -H 'Content-Type: application/json' \
     -d '{"name":"pac-positive","private":false,"auto_init":false}' \
     http://<HOST>:3000/api/v1/user/repos
```

**5. Build the local repository with a real remote and push through it.** The
push is what proves the remote is functional rather than decorative.
```
python testbed/setup_positive_access.py \
    --gitea-host <HOST> \
    --repo-dir out/positive_access_live/repo \
    --push
```

**6. Run the pipeline against the live environment.** The scan target must be the
same address the remote names, so that the rule can resolve one against the
other. `--version-all` is exhaustive; the measured runtime was 286 s.
```
export AETHERGRAPH_NMAP_TIMEOUT=900
python collectors/run_active.py <HOST> --ports 21,80,8080,3000 --out-dir out/positive_access_live
python collectors/run_secret_scan.py out/positive_access_live/repo \
    --active-jsonl out/positive_access_live/real_active.jsonl \
    --out-dir out/positive_access_live
python collectors/run_web_evidence.py --active-jsonl out/positive_access_live/real_active.jsonl \
    --out-dir out/positive_access_live --host <HOST>
python collectors/run_identity.py <HOST> --url http://<HOST> \
    --active-jsonl out/positive_access_live/real_active.jsonl \
    --web-evidence-jsonl out/positive_access_live/real_web.jsonl \
    --out-dir out/positive_access_live
python collectors/run_manual.py --active-jsonl out/positive_access_live/real_active.jsonl \
    --host-alias 127.0.0.1 --out-dir out/positive_access_live
```

**7. Evaluate and write the report.**
```
python scripts/run_positive_access_experiment.py
```

## Negative controls

Both use the same live token and repository; only the evidence differs.

```
# (a) remote removed -> rule must decline
git -C out/positive_access_live/negative_control/repo remote remove origin
python collectors/run_secret_scan.py out/positive_access_live/negative_control/repo \
    --active-jsonl out/positive_access_live/negative_control/real_active.jsonl \
    --out-dir out/positive_access_live/negative_control

# (b) Gitea observation withheld from the observed set -> rule must decline
python collectors/run_secret_scan.py out/positive_access_live/negative_control_unobserved/repo \
    --active-jsonl out/positive_access_live/negative_control_unobserved/real_active.jsonl \
    --out-dir out/positive_access_live/negative_control_unobserved
```

## Teardown

```
cd testbed && docker compose down -v      # -v also removes the Gitea volume and the issued token
```

## Note on the working tree

`out/positive_access_live/repo/config.py` contains a live token in its working
tree and history for the duration of the experiment. It lives under `out/`, is
not part of the committed source, and is destroyed by the teardown above.
Revoke the token in Gitea if the instance is kept.
